0-BOSQICH: ICHKI YURAK

Encryption Barrier va Memory Locking (mlock)

🔐 Shifrlash To'sig'i (AES-GCM-256)
  • Storage Backend (Disk) da barcha ma'lumotlar shifrlangan blob ko'rinishida yotadi.
  • Disk o'g'irlansa yoki nusxalansa ham — Master Key'siz ma'lumotni o'qib bo'lmaydi.
  • Har bir yozish/o'qish operatsiyasida AES-GCM shifrlash to'sig'idan o'tadi.
🧠 mlock (Memory Lock) Mexanizmi
  • Linux OS xotira to'lganda RAM ma'lumotlarini diskdagi SWAP faylga chiqaradi.
  • mlock Vault xotirasidagi parollarni SWAP ga yozilishini jismonan to'sadi.
  • Zarur sozlama: setcap cap_ipc_lock=+ep /usr/bin/vault.
0-BOSQICH: MUHRLASH

Shamir's Secret Sharing va Vault Holatlari

🔑 Shamir Mexanizmi: Nega 1 Kishi Ocholmaydi?
  • Master Key bir nechta bo'lakka bo'linadi (Key Shares = 5).
  • Uni qayta tiklash uchun minimal kalitlar soni belgilanadi (Threshold = 3).
  • 3 ta alohida mas'ul admin o'z kalitini kiritmaguncha server xotirasi ochilmaydi.
🔄 Vaultning 4 Ta Asosiy Holati
StatusTa'rifi
UninitializedYangi o'rnatilgan, kalitlar hali mavjud emas.
SealedServer ishlayapti, lekin xotiradagi Master Key o'chirilgan, javob bermaydi.
UnsealedThreshold kalitlar kiritildi, shifrlash to'sig'i ochildi.

sudo systemctl enable --now vault
sudo systemctl enable --now vault-auto-unseal

# Initsializatsiya
export VAULT_ADDR="http://127.0.0.1:8200"
vault operator init -key-shares=5 -key-threshold=3

# Muhrni ochish
vault operator unseal <UNSEAL_KEY_1>

2-KUN AMALIYOT

KV v2 Buyruqlar Bazasi va REST API

BASH CLI 
# Yozish (Put)
vault kv put secret/organizations/sarvartech/billing/prod \
    db_user="db_admin" \
    db_pass="SuperSecret@2026"

# Qisman yangilash (Patch)
vault kv patch secret/organizations/sarvartech/billing/prod \
    api_key="sk_live_9921"

# O'qish (Get) va Versiyalar
vault kv get secret/organizations/sarvartech/billing/prod
vault kv get -version=1 secret/organizations/sarvartech/billing/prod
REST API (cURL) 
# HTTP GET orqali secretni o'qish
curl -s -H "X-Vault-Token: $TOKEN" \
  https://vault-srv.sarvartech.uz/v1/secret/data/organizations/sarvartech/billing/prod \
  | jq '.data.data'

# Soft-delete va Undelete
vault kv delete -versions=2 secret/organizations/sarvartech/billing/prod
vault kv undelete -versions=2 secret/organizations/sarvartech/billing/prod
AMALIYOTCHI BOSQICHI

Tokenlar Turlari, TTL va Accessor Mexanizmi

🎟️ Token Turlari va Xususiyatlari
  • Service Token: Standart token. Vault xotirasida saqlanadi, ota-bola bog'liqligi bor.
  • Batch Token: Xotirada saqlanmaydi (stateless). Juda yuqori RPS va tezkor so'rovlar uchun.
  • Orphan Token: Otasi yo'q token. Agar otasi revoke bo'lsa ham bu token tirik qoladi.
  • Num_uses cheklovi: -use-limit=1 orqali faqat bir marta o'qiladigan token yaratiladi.
TOKEN ACCESSOR AMALLARI 
# 1. 2 soatlik cheklangan token yaratish
vault token create -ttl=2h -use-limit=2 -policy=billing

# 2. Accessor orqali tokenni qidirish (Tokenning o'zini bilmasdan!)
vault token lookup -accessor "a6KNiBTnyMT..."

# 3. Accessor orqali bekor qilish (Revoke)
vault token revoke -accessor "a6KNiBTnyMT..."
DEVSECOPS BOSQICHI

ACL Policies (Ruxsatnomalar Yozish San'ati)

HCL (billing-policy.hcl) 
# Faqat billing servisiga o'qish ruxsati berish
path "secret/data/organizations/sarvartech/billing/*" {
  capabilities = ["read", "list"]
}

# Metadatasini ko'rish
path "secret/metadata/organizations/sarvartech/billing/*" {
  capabilities = ["list", "read"]
}

# Boshqa hamma yo'llar taqiqlanadi (Default Deny)
path "secret/*" {
  capabilities = ["deny"]
}
🛡️ ACL Capabilities Tahlili
  • create — Yangi secret yaratish imkoni.
  • read — Mavjud secretni o'qish.
  • update — Mavjud secret ustiga yozish / patch qilish.
  • delete — O'chirish (soft delete yoki metadata delete).
  • sudo — Faqat tizim administratorlari uchun xavfli ruxsat (oddiy dasturchiga berilmaydi!).
DEVSECOPS BOSQICHI

Dinamik Database Parollari (PostgreSQL / MySQL)

🔄 Nega Statik Baza Parollari O'tmishda Qoldi?
  • Agar bitta dasturchi parolni bilsa yoki logga tushsa — butun baza xavf ostida qoladi.
  • Vault har bir ilova so'rovida bazada yangi foydalanuvchi yaratadi: v-approle-xyz.
  • Unga faqat 1 soatlik umr (TTL = 1h) beriladi.
  • Muddati o'tgach — Vault ushbu userni bazadan jismonan o'chiradi (REVOKE & DROP).
BASH DATABASE ENGINE 
vault secrets enable database

vault write database/config/postgresql \
    plugin_name=postgresql-database-plugin \
    allowed_roles="billing-role" \
    connection_url="postgresql://{{username}}:{{password}}@localhost:5432/bank_db" \
    username="vault_admin" \
    password="VaultAdminPassword"

# Har safar yangi 1 soatlik parol olish:
vault read database/creds/billing-role
MASTER ADMIN BOSQICHI

PKI Engine: Dinamik TLS/SSL Sertifikatlari

🔐 Avtomatik Ichki CA (Certificate Authority)
  • Vault ichki korporativ CA vazifasini bajaradi.
  • Mikroservis ishga tushganda Vaultdan 30 kunlik o'ziga xos X.509 TLS sertifikat oladi.
  • Har 15 kunda avtomatik yangilanadi (Zero-downtime mTLS).
  • Qo'lda sertifikat o'rnatish va muddati o'tib to'xtab qolish xavfi yo'qoladi.
PKI SERTIFIKAT GENERATSIYASI 
vault secrets enable pki

vault write pki/root/generate/internal \
    common_name="SarvarTech Internal CA" \
    ttl=87600h

# Mikroservisga dinamik sertifikat berish
vault write pki/issue/internal-services \
    common_name="billing.sarvartech.uz" \
    ttl="720h"
MASTER ADMIN BOSQICHI

Transit Engine: Shifrlash Xizmati (EaaS)

🛡️ Encryption as a Service Tamoyili
  • Ma'lumot Vaultda SAQLANMAYDI.
  • Ilova Vaultga ochiq matn (masalan, pasport yoki karta raqami) yuboradi.
  • Vault uni AES-GCM bilan shifrlab qaytaradi: vault:v1:8f7e....
  • Ilova o'z bazasida faqat shifrlangan satrni saqlaydi.
  • O'qish kerak bo'lganda — Vaultga berib yechtirib oladi (transit/decrypt).
TRANSIT ENCRYPT / DECRYPT 
vault secrets enable transit
vault write -f transit/keys/customer-cards

# Shifrlash (Encrypt)
vault write transit/encrypt/customer-cards \
    plaintext=$(echo "8600 1234 5678 9900" | base64)

# Shifrni yechish (Decrypt)
vault write transit/decrypt/customer-cards \
    ciphertext="vault:v1:s8D..."
MASTER ADMIN BOSQICHI

Audit Logging: Bank Darajasidagi Nazorat

📜 Fail-Closed Tamoyili
  • Agar Audit qurilmasi (File yoki Syslog) ishlamasa yoki disk to'lib qolsa — Vault yangi so'rovlarni qabul qilishni to'xtatadi!
  • Barcha maxfiy kalitlar va tokenlar logga tushishdan oldin HMAC-SHA256 orqali xeshirlanadi (parollar ochiq holda ko'rinmaydi).
AUDIT YOQISH VA JONLI TAHLIL 
# 1. Fayl audit qurilmasini yoqish
vault audit enable file file_path=/var/log/vault/vault_audit.log

# 2. Real-time audit oqimini kuzatish (jq bilan)
tail -f /var/log/vault/vault_audit.log | jq '{
  time: .time,
  type: .type,
  path: .request.path,
  ip: .request.remote_address,
  error: .error
}'

ZAXIRALASH VA TIKLASH

Raft Snapshot (DR) va Production Doctor

SNAPSHOT SAVE & RESTORE 
# 1. Zaxira nusxa (Snapshot) olish
vault operator raft snapshot save /backups/vault_backup_$(date +%F).snap

# 2. Server halokatga uchraganda to'liq qayta tiklash
vault operator raft snapshot restore -force /backups/vault_backup_2026-09-29.snap

# 3. Statusni tekshirish
vault status
🩺 Production Doctor Har Kuni Tekshiradigan 6 Nuqta
  • Vault holati (Sealed: false).
  • Auto-unseal servisi (vault-auto-unseal faolmi?).
  • Disk xotirasi (80% dan oshmasligi lozim).
  • Audit log hajmi va rotatsiyasi (logrotate).
  • Nginx Reverse Proxy va TLS sertifikat muddati.
  • RAM bandligi va mlock holati.
XATOLARDAN SABOQ

Administratorning 5 Ta Qat'iy Taqiqlangan Xatosi!

  • 1. Root tokenni dasturchilarga yoki .env fayllarga tarqatish: Root token faqat favqulodda holat uchun. Boshlang'ich sozlashdan keyin darhol bekor (revoke) qilinishi shart!
  • 2. Unseal kalitlarini serverning o'zida /root/keys.txt da qoldirish: Server buzilsa — Vault ham darhol dushman qo'liga o'tadi.
  • 3. Audit Device'ni yoqmasdan Productionga chiqish: Audit yo'q bo'lsa — kim qaysi parolni o'g'irlaganini hech qachon isbotlab bo'lmaydi.
  • 4. Hamma narsaga "secret/*" va "sudo" ruxsatlarini berish: Bu Vaultni shunchaki xavfli oddiy bazaga aylantirib qo'yadi.
  • 5. Zaxira nusxasini (Snapshot) tiklab ko'rmaslik: Sinovdan o'tmagan zaxira — bu umuman mavjud bo'lmagan zaxiradir!
